一、项目概述

1.1 背景

Hermes Agent 支持通过 TTS provider 配置实现语音播报能力。原生 OpenAI-compatible API 方案要求调用外部服务，但用户希望使用本地开源模型实现声音定制能力（Voice Design / Voice Cloning）。VoxCPM2 是 OpenBMB 团队开源的高质量语音合成模型，支持零样本声音克隆和自然语言音色设计。

1.2 选择 VoxCPM2 的理由

维度 说明
声音定制 支持零样本克隆 + 自然语言描述生成新音色（Voice Design）
开源协议 Apache 2.0，商用友好
质量 48kHz 高保真输出，中英语言支持良好
本地部署 M5 Max 128GB 可完整运行，无需 GPU
集成方式 FastAPI HTTP wrapper → OpenAI compatible API → Hermes TTS provider

五、关键实现细节与踩坑记录

5.1 Uvicorn Worker 进程模型 — 全局状态丢失 Bug ⚠️

问题：Uvicorn 默认启动多个 worker，每个 worker 是独立进程。全局变量 _model 在 main() 中设置的值在 worker 进程中丢失，导致首次请求时模型未加载。

修复方案：预加载 + 单 worker

5.2 from_pretrained 必须加 local_files_only=True ⚠️

问题：当 model path 是本地路径时，HuggingFace from_pretrained 会尝试从 HF Hub 下载。没有 token 时 XET 格式下载会卡住不动。

5.4 /api/clone 响应格式 — JSON vs Raw WAV ⚠️

问题：最初 /api/clone 返回 {"status":"ok","audio_data":"hex_string..."} JSON。浏览器 resp.blob() 拿到的是 JSON blob（application/json），无法被 <audio> 元素解码。

修复方案：直接返回原始 WAV bytes

八、整体复盘

8.1 技术决策回顾

决策 选择 理由
封装方式 HTTP API wrapper (FastAPI) 与 Hermes TTS provider 天然兼容，无需修改 Agent 核心代码
模型选择 VoxCPM2 (ModelScope) 国内下载速度快，支持 Voice Design + 声音克隆
响应格式 Raw WAV bytes (audio/wav) 浏览器 <audio> 元素和 Blob API 原生支持，无需前端解码
测试策略 TDD (RED-GREEN-REFACTOR) 每个 bug 修复都有测试覆盖，防止回归
模型加载 预加载 + 单 worker Uvicorn 多 worker 导致全局状态丢失的规避方案

8.2 Bug 修复历程

# Bug 根因 修复
1 from_pretrained 卡住不加载 本地路径未设置 local_files_only=True，HF XET 下载无 token 卡死 添加 is_local 判断 + local_files_only=is_local
2 _generate() 返回 .numpy() 报错 返回值是 np.ndarray 不是 Tensor 直接使用，去掉 .numpy() 调用
3 Worker 进程模型为 None Uvicorn fork 后全局变量丢失 预加载 + workers=1
4 /api/clone 返回 JSON 导致浏览器无法播放 响应格式为 {"audio_data":"hex"} 改为 Response(content=wav, media_type="audio/wav")
5 start_server.sh worker 进程找不到模型路径 变量未 export export VOXCPM_MODEL="$MODEL"
6 HTMLResponse import error FastAPI 不直接导出 HTMLResponse 从 starlette.responses 导入
7 Bash docstring 导致脚本执行失败 Python docstring 被 bash 解析 .sh 文件只使用 # 注释
8 Stale PID 导致重复启动误判 未检测进程是否存活 kill -0 检查 + stale PID 清理

8.3 经验总结

  1. Uvicorn worker 模型是最大坑：全局状态（加载的模型）在 fork 后丢失。解决思路有两种：预加载 + 单 worker（当前方案），或用 --reload 模式。生产环境建议用 workers=1 + 预加载。

  2. 响应格式决定前端兼容性：JSON hex-encoded audio → 浏览器无法识别；Raw WAV bytes → 原生支持。API 设计时就要考虑最终消费方（浏览器/客户端）的能力边界。

  3. TDD 的价值在回归保护：每次 bug 修复都先写测试，确保后续重构不会引入同样的问题。test_web_ui.py 从最初的 9 tests 增长到 18 tests，覆盖了所有已知场景。

  4. ModelScope vs HuggingFace：国内环境 ModelScope 下载速度快且稳定。HF XET 格式需要 token，否则大量小文件下载极易卡住。

  5. 声音克隆 vs 标准合成：/v1/audio/speech（OpenAI 兼容）通过 voice 参数区分，但需要本地文件路径；/api/clone（专用）支持直接上传参考音频。两者互补，满足不同使用场景。

8.4 后续优化方向

  • 流式输出：当前 _generate() 返回完整 WAV，长文本合成等待时间长。可探索 streaming mode
  • 并发处理：单 worker 限制吞吐量，后续可考虑 async queue + 预加载模型到共享内存
  • 声音管理：当前参考音频每次上传，可持久化存储声音库，支持选择已有音色
  • 多模型切换：支持加载多个 VoxCPM2 变体或不同 TTS 模型，动态切换
